# Deutsch und Englisch (#126) und die Ausgabe der Slash-Listen (#109)

Stand: 2026-10-30, **gegrillt** (Q1–Q23, Owner). Zwei Karten in einem Plan: #109 wird gleich mit Schlüsseln gebaut,
damit das neue Panel nicht zweimal angefasst wird.

## 1. Heute

- Die ganze Oberfläche ist Englisch (Owner, 2026-10-07: „UI komplett Englisch, später i18n“), ohne Übersetzungscode:
  rund 140 Svelte-Dateien, etwa 1.000–1.500 sichtbare Texte (≈ 350 `label`/`title`/`aria-label`/`placeholder`,
  ≈ 610 Zeilen Text zwischen Tags, 177 `toast(`), dazu Beschriftungen in `.ts` (z. B. `core/settingsTabs.ts`).
- Rund 100 Ablehnungen und Fehler aus Rust (`axiomata-core`) erscheinen wörtlich, meist über `messageOf(err)`.
- Datum und Zahlen: größtenteils `core/format.ts` (`toLocale*` mit Systemsprache), etwa 30 Stellen formatieren
  selbst, eine fest auf `de-DE` (`ide/cardUsage.ts`).
- Das Handbuch (`docs/handbook/`) ist Deutsch, per `include_str!` eingebettet (`axiomata_core::handbook`), der Chat
  liest es als Wissen; `core/handbook.ts` `PAGE_FOR_PLACE` verweist nach Dateiname.
- Glut hat eigene Mehrsprachigkeit ohne Bibliothek (`../Axiomata-Glut/crates/glut/src/lang.rs`): Kataloge als Code,
  ein fehlender Text in einer Sprache baut nicht; Sprache aus Flag, sonst System, sonst Englisch.
- Slash-Listen (`core/commands.ts`): `/help`, `/model` (bis 40 Modelle), `/skills`, `/resume`, `/cost` schreiben
  Markdown in den Chatverlauf; mehrere Listen stapeln sich.

## 2. Entscheidungen (Owner, 2026-10-30)

**#126 Sprachen**

- **Q1** Zweisprachig werden die Oberfläche, die Fehlermeldungen aus Rust und das Handbuch. Die CLI bleibt Englisch;
  alles, was ein Modell liest (Rollen, Startanweisungen, Skills, `APP_GUIDE`), bleibt Englisch.
- **Q2** Standard ist die macOS-Systemsprache; eine Einstellung überschreibt sie.
- **Q3** Englisch ist die Quelle und der Rückfall für Stellen ohne Schlüssel.
- **Q4** Jede Handbuchseite gibt es in beiden Sprachen; App und Chat nehmen die der eingestellten Sprache; der
  Coverage-Test verlangt beide. Als letzter Schritt.
- **Q5** Schrittweise, Bereich für Bereich, je mit Review; ein Test meldet sichtbare Texte ohne Schlüssel.
- **Q10** Kataloge in TypeScript wie bei Glut: `en` als Quelle, `de` mit genau derselben Form — `npm run check`
  schlägt fehl, wenn ein deutscher Text fehlt. Benannte Platzhalter (`{n}`), Mehrzahl eigens (eins / mehrere). Eine
  Katalogdatei je Bereich (`shell`, `studio`, `kanban` …).
- **Q11** Ablehnungen aus Rust bekommen einen festen Code mit Werten (z. B. `role.unknown {name}`); das Frontend
  übersetzt bekannte Codes, unbekannte erscheinen weiter Englisch; die CLI bleibt Englisch. Häufigste zuerst.
- **Q12** Datum und Zahlen nur über `core/format.ts`, nach der App-Sprache; die ~30 eigenen Stellen wandern dorthin.
- **Q13** Namen bleiben Englisch: Studio, Canvas, Flow, Kanban, Second Brain, Orbit, Skills, Routines, Master, die
  Stufen Light/Medium/Heavy, die Rollennamen. Übersetzt werden Handlungen, Hinweise, Erklärungen.
- **Q14** Umschalten sofort, ohne Neustart (die Sprache ist ein Store).
- **Q15** Das englische Handbuch übersetzt Claude einmal; danach ändert jede Änderung beide Fassungen im selben
  Commit (Regel in `AGENTS.md`, Coverage-Test).
- **Q16** Der Chat bekommt eine Zeile „The owner's language is German; answer in it.“, nach der App-Sprache.
- **Q20** Die deutsche Oberfläche duzt.
- **Q21** Einstellung in Settings → Appearance: „Language: System · Deutsch · English“; im Handbuch auf der Seite zu
  den Einstellungen.
- **Q22** Englische Seiten unter `docs/handbook/en/` mit denselben Dateinamen; die App wählt den Ordner.
- **Q23** Keine Gender-Formen, nirgends (kein „Nutzer*innen“, kein „Benutzende“): einfaches Deutsch, du-Form.

**#109 Slash-Listen**

- **Q6** Listen erscheinen in einem Panel über der Eingabezeile (wie das `/`-Vorschlagsmenü), ersetzen die vorige,
  schließen mit Esc oder Klick daneben, landen nie im Verlauf.
- **Q7** Ein Klick handelt: `/model` wählt, `/resume` setzt fort, `/skills` startet nach „Run ‹name›?“, `/help`
  setzt das Kommando in die Zeile (ein Thema öffnet die Handbuchseite).
- **Q8** Tippen filtert (`/model deep`), ↑↓ wählt, ⏎ übernimmt; Spalten je Liste (Modelle: Name, Preis, Kontext;
  Gespräche: Titel, Datum; Skills: Name, Beschreibung); etwa 8 Einträge sichtbar, dann scrollt es.
- **Q9** Auch `/cost` erscheint dort, als kleine Tabelle; keine Kommando-Ausgabe mehr im Verlauf.
- **Q17** Überall, wo die Chat-Leiste der App steht (Dashboard, angedocktes Chat-Panel); nicht in Glut-Panes.
- **Q18** `/model` mit einer ID, die nicht gelistet ist: ⏎ übernimmt sie (geprüft wie heute); das Panel zeigt
  „Use ‹id›“.

## 3. Bau

- **I1 Technik:** Kataloge mit Typprüfung, Platzhalter und Mehrzahl, Sprachwahl (System, Einstellung, Store, sofort),
  `format.ts` nach Sprache (die ~30 Stellen umgezogen, `de-DE` weg), Einstellung unter Appearance, Test „kein
  sichtbarer Text ohne Schlüssel“ für die schon umgestellten Bereiche. Handbuch-Zeile, Chat-Zeile (Q16).
- **I2 Slash-Panel (#109):** Q6–Q9, Q17, Q18, von Anfang an zweisprachig.
- **I3 Shell und Settings** · **I4 Studio** · **I5 Kanban** · **I6 Brain und Notizen** · **I7 Module** — je
  Bereich die Texte auf Schlüssel, Deutsch geschrieben nach Q13/Q20/Q23.
- **I8 Fehlercodes aus Rust** (Q11), die häufigsten zuerst.
- **I9 Englisches Handbuch** (Q4, Q15, Q22), Regel in `AGENTS.md`, `docs/architecture.md` nachgezogen.

Prüfungen: der volle Gate je Schritt; ein kombinierter Review-Agent je Schritt; Sicht im Browser-Mock in beiden
Sprachen.
